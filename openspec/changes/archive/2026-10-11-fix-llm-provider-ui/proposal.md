# Proposal: fix-llm-provider-ui

## Why

用户实机使用 `llm-multi-provider` 后指出两处问题（用户直接下了修复指令「改」）：

1. **下拉点不开**：供应商弹窗的「平台预设」、页面的「当前使用」在**真实鼠标点击**下不可用——`#drop-menu` 的全局「点外关闭」监听器只白名单了旧触发器（`#model-pill` / `#lora-pick` / `.feed-pill`），新触发器不在名单里：菜单打开后同一次点击继续冒泡即被收起。开发期走查用 JS `.click()`（隐藏元素也能点）掩盖了该问题；「已拉取模型」同属此列。
2. **弹窗布局差**：供应商弹窗沿用页面级 `.set-row` 行式（标签贴左、控件贴右缘、中间大段空档），不符合用户参考项目（`xiaoheihe_crawler/sentiment-monitor`）的对话框版式——标签列固定宽 + 控件列占满、拉取后独立「已拉取模型」下拉、底部「取消 / 保存」按钮行、启用为开关。

## What Changes

**（视觉变更：供应商弹窗重排为「标签列 + 控件列」对话框版式）**

1. **下拉可点击性根因修复**：全局点外关闭白名单引入通用标记 `data-drop-opener`（保留旧白名单），「平台预设 / 当前使用 / 已拉取模型」触发器全部标注；
2. **供应商弹窗重做（对齐参考项目版式）**：标签列 92px + 控件列占满（输入框全宽）；「默认模型 = 输入框 + 拉取模型」同行；拉取成功后出现「已拉取模型」下拉（openDrop，选中回填，未填自动取第一个）；「启用」用既有 `.switch` 橙色开关；底部「取消 / 保存」右对齐按钮行；API Key 行带「清除 Key」（编辑态）；
3. **验证方式**：本次全部用**真实鼠标点击**（Playwright 真点击）复测，不再用 JS `.click()` 走查交互。

非目标（Non-goals）：不改供应商接口与数据语义；不改试聊面板；设置类页面维持既有标签/控件行式。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `web-ui-design`: 新增「供应商编辑弹窗版式」要求（标签列 + 控件列、已拉取模型下拉、底部按钮行、开关；openDrop 触发器 MUST 标注 `data-drop-opener`）。

## Impact

- **前端**：`web/static/app.js`（白名单 + 弹窗重写 + 触发器标注）、`web/static/styles.css`（`.llm-form-*` 版式类）、`web/static/i18n.js`（`llm.fetchedModels`）。
- **测试**：真实点击复测通过；原有 294 项单测不受影响（纯前端交互与版式）。
- **风险**：低——新增标记与既有白名单兼容；弹窗仅本页使用。
